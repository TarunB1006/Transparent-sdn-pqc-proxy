⚠ Scale-Out Recommended
Manual Scale-Out
Assign a fat-tree pod to a new controller. In production this maps to starting a separate ryu-manager instance with domain_dpids set to the pod's switches. Controllers communicate indirectly via the shared Plan API — each controller manages its own sessions and forwards inter-domain flow decisions through the root controller.


How Controllers Coordinate

Session isolation: Each controller runs its own ControlPlaneService with a domain_dpids filter. Handshake requests for out-of-domain switches are rejected immediately — no cross-controller session leakage.

Shared Plan API: All controllers publish session keys to the same Plan API endpoint (:8080). Switch proxies poll this single endpoint regardless of which controller performed the handshake.

Inter-domain routing: Cross-pod flows (e.g. edge-pod0 → edge-pod1) traverse core switches managed by the root controller. The root controller installs forwarding rules on core switches; pod controllers install rules on their own agg+edge switches. ECMP selects the least-loaded core path.

Load balancing trigger: A controller is flagged overloaded when it manages more than switch_threshold switches OR average handshake latency exceeds latency_threshold. The platform then recommends migrating a pod's switches to a new controller domain, reducing per-controller session count and handshake CPU load proportionally.
